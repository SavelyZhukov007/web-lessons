# Функциональная проверка админки — Виктория Пичкур

Дата: 22 октября 2026 года. Проверена текущая папка проекта. Использованы только вымышленные QA-данные и отдельная тестовая SQLite-база; рабочая `backend/development.sqlite3` не использовалась.

## Как повторить

Установить зависимости из `backend/requirements.lock.txt`, затем из корня проекта выполнить:

```powershell
python -m pytest backend/tests -q
```

В этой проверке использован Python 3.12.14 и версии зависимостей из lock-файла. Тесты в `backend/tests/test_admin_functional_qa.py` используют фикстуры `conftest.py`: таблицы создаются заново для каждого сценария, а файл `test.sqlite3` удаляется после прогона. Проверки написаны для маршрутов, уже имевшихся в проекте: после запроса проверяются HTTP-код, схема и значения JSON-ответа, а затем сохранённое состояние через GET. Идея взята из [статьи об API-автотестах](https://habr.com/ru/articles/765512/); её пример для стороннего сервиса и отдельную инфраструктуру логов проекту не переносили.

Для проверки страниц запущен локальный сервер на `127.0.0.1:8765` с отдельной `qa_browser.sqlite3`. Проверены размеры окна 1280×800 и 390×844. На обеих доступных страницах горизонтальной прокрутки нет (`scrollWidth` совпал с шириной окна). Это подтверждает только вёрстку текущих заглушек, а не будущих списков и форм.

## Результаты сценариев

| Сценарий | Результат | Подтверждение |
|---|---|---|
| Создать, изменить и удалить направление, руководителя, аудиторию, кружок и регулярное занятие | Пройдено на API | Независимые тесты CRUD справочников, кружка и занятия; сохранение проверено через GET |
| Скрыть кружок и вернуть его в публичный список | Пройдено на API | После `is_active=false` публичный список пуст, административный список сохраняет запись; после `true` кружок виден снова |
| Запретить удаление используемого направления, руководителя и аудитории | Пройдено на API | `DELETE` возвращает `409`; после удаления связей возвращает `204` с пустым телом |
| Отклонить некорректные данные и сохранить уже записанные значения | Пройдено на API | Пустое имя, нулевая вместимость и неверный интервал дают `422`; повторное имя направления даёт `409`; ранее сохранённое время не меняется |
| Создать, изменить и удалить отмену и перенос | Пройдено на API | Отдельные тесты жизненного цикла отмены и переноса; изменения видны в публичном расписании |
| Отклонить повторную отмену одного занятия | Пройдено на API | `409`, исходная отмена доступна для изменения и удаления |
| Отклонить неверное новое время переноса без порчи записи | Пройдено на API | `422`, прежнее время остаётся в списке исключений |
| Отклонить наложение занятий в одной аудитории и у одного руководителя | **Дефект вне текущего покрытия** | При исследовательской проверке API возвращал `201` вместо `409`; серверное правило ещё не встроено в административный маршрут |
| Войти, открыть панель, создать и изменить данные через HTML-формы | **Заблокировано** | Форма входа сообщает «Вход ещё не реализован»; панель содержит только текст-заглушку |
| Проверить в браузере `401`, `409`, `422`, сохранение введённых полей, подтверждение удаления, защиту от повторной отправки | **Заблокировано** | Форм управления данными пока нет. Проверка API-ответов не подтверждает поведение интерфейса |
| Проверить телефон и компьютер | Частично | Существующие страницы входа и панели просмотрены при 390×844 и 1280×800; функциональные экраны ещё отсутствуют |

Новый файл функциональных тестов содержит 16 проверок API. В этом клоне полный набор пока имеет одно старое падение в `test_template.py`: тест ожидает `501`, хотя `/api/clubs` возвращает `200`. Два прежних TODO-теста пропускаются. Для проверки именно этой QA-работы запускайте `python -m pytest backend/tests/test_admin_functional_qa.py -v`.

## Воспроизводимые дефекты

### QA-ADM-01 — панель недоступна как рабочий интерфейс (блокирующий)

1. Открыть `http://127.0.0.1:8765/admin/login.html` на локальном тестовом сервере.
2. Ввести любой непустой тестовый логин и пароль, нажать «Войти».
3. Появляется «Вход ещё не реализован. Доступ к API закрыт.»; перехода в панель нет.
4. Открыть `/admin/index.html` напрямую: виден только текст «Здесь будут списки и формы», без CRUD-форм и списков.

Ожидается рабочий вход и экраны управления. Ответственные за исправление: Алина Романчева (вход), Алиса Маркарова (основные экраны). После их изменений повторить все сценарии через UI на телефоне и компьютере.

### QA-ADM-02 — наложение занятий сохраняется (высокий приоритет)

1. Через административный API создать направление, руководителя, аудиторию и два кружка с одним руководителем.
2. Создать занятие первого кружка во вторник 15:00–16:00 в созданной аудитории.
3. Создать занятие второго кружка во вторник 15:30–16:30 в той же аудитории.
4. Фактически второй `POST /api/admin/sessions` возвращает `201`; ожидается `409` с причиной конфликта.
5. Повторить шаг 3 с другой аудиторией, оставив того же руководителя: снова `201` вместо `409`.

Серверные правила сохранения относятся к команде A; передать дефект ей, не дублировать правило во frontend. В текущий набор автотестов этот ожидаемый, но ещё не реализованный функционал не включён согласно уточнению задания: тесты охватывают то, что уже было в репозитории.

### QA-ADM-03 — устаревшая проверка шаблона в текущем клоне

`test_template_routes` ожидает `501` от `/api/clubs`, хотя маршрут уже отвечает `200`. Эта строка находится в старом тесте проекта и в текущий QA-коммит не входит. При полном прогоне её нужно исправить отдельно.

## Что повторить после реализации экранов

1. На телефоне 390×844 и компьютере 1280×800 пройти вход, выход и возвращение на страницу после истечения сессии.
2. Для каждого справочника, кружка и занятия создать запись, увидеть её в списке, изменить, удалить через подтверждение и проверить обновление списка без перезагрузки.
3. Скрыть кружок: убедиться, что он остаётся в админке, пропадает из публичного списка и возвращается при повторном включении.
4. Создать отмену и перенос; изменить и удалить исключение; сверить исходную и новую недели в публичном расписании.
5. Для каждой формы вызвать `422` и `409`: сообщение должно объяснять причину, введённые поля должны остаться заполненными, повторное нажатие не должно создать дубль.
6. Проверить длинные названия и сообщения, навигацию с клавиатуры, отсутствие горизонтальной прокрутки и перекрытия элементов на обоих размерах.

Проверки неавторизованных запросов, неверных/истёкших сессий и утечки служебных сведений закреплены за Алисой Жуковой; этот отчёт не заменяет её проверку доступа.
