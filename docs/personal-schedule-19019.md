# KipClub 1.9.019 / Android code 36 — личное расписание

## Реализовано

- Общие web/PWA/Android-модели «Сейчас» и старта в следующие 15 минут, прогресс без изменения геометрии карточки. Обновление раз в 30 секунд и при возвращении на экран, без перерисовки списка.
- Отдельное занятие в календарь: системный Android ACTION_INSERT с подтверждением пользователем (без прямой записи/разрешения календаря); web/PWA — один VEVENT в ICS, UTF-8 folding, UTC и стабильный UID. Импорт/шторку календаря на настоящем iPhone нужно проверить отдельно.
- Избранные руководители и аудитории (не роли): до 50 каждого типа на устройстве, кнопки в занятии, список/удаление в настройках, ссылки и приоритет в фильтрах.
- Сохранённая неделя показывает время данных в МСК. Время не переписывается свежим при чтении офлайн-копии.
- Общая форма: N от 0 до 120 минут (0 выключает), тихие часы через полночь, утренний дайджест «Моих кружков». Все часы — московские. Новые quiet/digest выключены по умолчанию; web reminders тоже выключены до явного сохранения. Существующие native напоминания сохраняют прежнюю настройку.
- Web: миграция 0015, настройки привязаны к существующей подписке; очередь с хешированным адресатом, без копии endpoint/ключей. Планировщик каждые 30 секунд, catch-up 10 минут для reminders / 15 минут для digest. Перед доставкой проверяются согласие, подписки, актуальное занятие/отмена/перенос. Истёкшие напоминания не отправляются; изменённый N заменяет только неотправленное. Атомарный claim, lease 2 минуты, timeout транспорта 10 секунд, максимум 3 попытки; стабильный tag защищает клиент от повторного показа/счёта. Устаревшие задачи очищаются.
- Android: локальные alarm reminders, opt-in дайджест по сохранённым данным, bounded quiet queue 100 / 48 часов с проверкой категорий и актуальных подписок; уважает разрешения ОС/exact-alarm. Повторяющаяся доставка FCM/polling по-прежнему дедуплицируется существующим Push.claim.
- SW группирует уведомления по типу/кружку за московские сутки, сериализует конкурентные push, ограничивает историю. Каждая userVisibleOnly доставка всё равно показывает/обновляет уведомление. Значок не считает повторный tag. Ротация endpoint сохраняет ровно прежние quiet/reminder/digest настройки и не расширяет согласие.

## Ограничения

- Это best-effort напоминания, не будильник: iOS/PWA и Android без exact-alarm могут задержать доставку; без сохранённого расписания Android дайджеста нет. Offline native использует последний снимок, поэтому изменения требуют синхронизации.
- HTTP TEST не даёт настоящую установленную iOS PWA/SW. Проверки PWA проведены на безопасном localhost с реальным SW/БД и mock доставки; реальный iPhone требует пользовательской проверки.
- Не изменены env, secrets, compose, modal-scroll-lock; новые роли/неделя вперёд/QR/security/rate-limit/monitoring/canary не добавлялись.
