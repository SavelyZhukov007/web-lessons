# Ручная проверка админки

## Подготовка

1. Установить зависимости и запустить сервер по инструкции из `README.md`.
2. Создать администратора командой `python -m backend.scripts.create_admin`.
3. Открыть `http://127.0.0.1:8000/admin/login.html`.

## Чек-лист

1. Попытка открыть `http://127.0.0.1:8000/admin/index.html` без входа должна перенаправить на страницу логина.
2. `GET /api/admin/status` без cookie должен вернуть `401`.
3. Вход с неверным паролем должен вернуть ошибку.
4. Вход с корректным логином и паролем должен открыть панель управления.
5. В админке должны успешно создаваться и редактироваться:
   - направления;
   - руководители;
   - аудитории;
   - кружки;
   - регулярные занятия.
6. Для кружка должна работать смена статуса `is_active` без удаления записи.
7. Для регулярного занятия должны работать:
   - отмена конкретной даты;
   - перенос конкретной даты с новой датой, временем и аудиторией;
   - редактирование и удаление этих исключений.
8. После выхода `POST /api/admin/logout` повторный запрос к `/api/admin/status` должен снова вернуть `401`.

## Что пока не проверяется автоматически

- автоматическое обнаружение конфликтов аудиторий и руководителей на уровне административного API;
- загрузка стартового набора данных из `data/sample-data.json` служебным скриптом.
