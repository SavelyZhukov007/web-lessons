# Развёртывание в колледже: пошагово и честно

Для кого: человек, который будет ставить и поддерживать сервис в колледже (не обязательно программист). Общая схема — `docs/deploy.md`, эксплуатация — `docs/runbook.md`.

**Как читать статусы:** ✅ реализовано и проверено автотестами в разработке; 🟡 реализовано, но проверить нельзя без вашей инфраструктуры (или нужно решение владельца); ❌ не сделано. Подробно по 74 пунктам — `docs/PROD_STATUS.md`.

## 0. Что нужно решить до установки
| # | Вопрос | Почему важно | Приоритет |
|---|---|---|---|
| 1 | Где будет жить сервер: облачная VPS / сервер колледжа (Linux) / Windows-сервер | от этого зависит способ запуска (раздел 2) | P0 |
| 2 | Домен и доступ снаружи: публичный домен (HTTPS «из коробки», нужны порты 80/443) или внутреннее имя (`clubs.lan`, нужен внутренний сертификат) | без HTTPS cookie админа не будут `Secure`, push и установка PWA не заработают | P0 |

| 5 | Что такое «учебный период/каникулы» (`docs/domain-term.md`, DOM-01) | пока расписание — недельное повторение + исключения | P1 |
| 6 | Нужна ли iPhone-аудитория (push на iOS только из «Домой»-PWA) и Android-приложение (APK вне Google Play) | см. разделы 5–6 | P2 |

## 1. Требования
- Linux-сервер с Docker + Compose **или** Python 3.10+ (проверено на 3.10 и 3.13). 1 vCPU / 512 МБ достаточно (scrypt при входе временно занимает ~64 МиБ).
- SQLite в одном файле, **ровно один воркер** (запись сериализуется в процессе; несколько воркеров запрещены).
- Исходящий доступ к push-сервисам (FCM/Mozilla/Apple) — только если нужны уведомления.

## 2. Установка
### Вариант A — Docker Compose (рекомендуется)  🟡 (файлы написаны, `docker build`/`compose`/Caddy в разработке не запускались)
```bash
git clone <репозиторий> clubs && cd clubs
cp deploy/.env.example .env
# отредактировать: SITE_ADDRESS, ALLOWED_HOSTS, JWT_SECRET (python -c "import secrets;print(secrets.token_urlsafe(48))"), VAPID_SUBJECT
docker compose up -d --build
docker compose exec app python server.py admin create admin      # спросит пароль (≥10 символов)
docker compose exec app python server.py seed                    # демо-данные, по желанию
curl -fsS https://<домен>/readyz
```
Внутренний адрес без публичного домена: `SITE_ADDRESS=clubs.lan`, `CADDY_TLS=tls internal`, затем добавить корневой сертификат Caddy в доверенные на устройствах (иначе браузер и PWA будут ругаться).

### Вариант B — без Docker (systemd)  🟡
Файлы `deploy/clubs.service`, `clubs-backup.service`, `clubs-backup.timer`; каталог `/opt/clubs`, конфиг `/etc/clubs/clubs.env` (права 600). Готовый пакет для этого варианта: `python server.py build back` → `builds/back/clubs-backend.zip` (внутри `RUN.md`).

### Вариант C — Windows-сервер  🟡
`py -3.10 -m venv .venv; .\.venv\Scripts\pip install -r backend\requirements.lock.txt; .\.venv\Scripts\python server.py serve --host 127.0.0.1 --port 8000 --no-reload --frontend builds\web` с `ENV=production` и обратным прокси (Caddy/IIS ARR) для HTTPS. Службой — через NSSM или планировщик заданий. **Не проверялось** (Windows-сервера в разработке не было; сам CLI запускался на Linux и Python 3.10).

## 4. После установки: 15 минут на проверку
1. `/` открывается, расписание и фильтры работают; `/admin/login.html` — вход; `/docs` → 404.
2. Создай тестовый кружок и занятие; попробуй создать второе в том же кабинете и то же время — должен прийти конфликт 409 с понятным сообщением.
3. Отмени занятие — в журнале (`docker compose logs app | grep admin_write`) появилась запись.
4. `docker compose exec app python server.py backup --dir /backups` и `verify-backup` — оба без ошибок.
5. Перезапусти контейнер — данные на месте.

## 5. Push-уведомления  🟡
Web Push (VAPID) реализован и протестирован на уровне API и подписки; **доставка на реальные устройства не проверялась** (нужны HTTPS и живой push-сервис). Ключи создаются автоматически и лежат в `VAPID_KEYS_FILE` на томе `/data` — **их нужно бэкапить и не терять**: при потере ключа все подписки перестанут работать. На iPhone push работает только из PWA, добавленной «На экран Домой» (iOS 16.4+). Нативный FCM для APK не делался.

## 6. Приложения
- **PWA** (`python server.py build pwa` → `builds/pwa`): устанавливается из браузера; инструкция для iOS выводится сборкой. 🟡 на реальном iPhone не проверялось.
- **Android APK** (`python server.py build android`): Capacitor 8, JDK 21, compileSdk 36. Адрес сервера задаётся в самом приложении (экран «Сервер») или при сборке `--server-url`. Подробно: `docs/ANDROID_APK.md`. Если сервер по HTTPS с публичным сертификатом — всё просто; для `http://IP:порт` в локальной сети включён cleartext (только для отладки).

## 7. Обновления и откат
Перед каждым обновлением — `server.py backup`. Обновление: `git pull && docker compose up -d --build` (миграции применяются при старте). Откат: прошлый тег + восстановление БД из бэкапа (миграции «вниз» не гарантируются). Подробно — `docs/runbook.md`.

## 8. Известные ограничения
- SQLite и один процесс: хватает на сотни пользователей; масштабирование вширь потребует PostgreSQL (не сделано).
- Покрытие тестами бэкенда 94 % (цель 95 %); в CI порог 92 %; CI на GitHub не запускался (🟡 OPS-04).
- Нет автоматической проверки доступности (axe/Lighthouse): контраст проверен юнит-тестами (WCAG AA) и скриншотами.
- Лицензия и `CODEOWNERS` — заглушки до решения владельца.
