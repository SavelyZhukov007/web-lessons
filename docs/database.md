# База данных

SQLite (WAL, `foreign_keys=ON`, `busy_timeout`). Путь: `CLUBS_SCHEDULE_DB_PATH` (в production — вне репозитория, том `/data`); по умолчанию dev-файл `development.sqlite3` в корне репозитория (в `.gitignore`).

**Схема управляется Alembic** (`backend/migrations`); текущая цепочка заканчивается ревизией `0017`. В ней есть базовая схема и авторизация, push и рассылки, учебные периоды, назначения аудиторий/руководителей, черновики и публикации импорта, личные уведомления и анонимная телеметрия. Миграция `0007` удалила таблицы посещаемости и QR; это не описание текущей схемы. Подробности расписания — в [schedule-v2-contract.md](schedule-v2-contract.md). При старте приложение применяет миграции (`prepare_database()`); пустая БД и БД, созданная до Alembic, штампуются корректно. Тесты используют `CLUBS_USE_CREATE_ALL=1` (быстро), отдельный тест проверяет цепочку миграций и совпадение со схемой моделей.

| Таблица | Назначение |
|---|---|
| `admins`, `admin_sessions` | администраторы (scrypt-хеш) и серверные сессии (`sha256(jti)`, срок) |
| `login_attempts` | счётчик неудачных входов для лимитера |
| `installs` | учёт установок, используемый для метаданных приложения |
| `categories` (цвет обязателен `#RRGGBB`), `leaders`, `rooms` | справочники |
| `clubs` | кружки (`is_active` скрывает кружок) |
| `sessions` | занятия: кружок, день/время, период и тип повтора; основные аудитория и руководитель сохраняются для совместимости |
| `session_exceptions` | отмены/переносы: уникально `(session_id, original_date)`, поля `new_*` |
| `push_subscriptions` | Web Push: `endpoint`, ключи, `club_id` (NULL = все изменения), `announcements` (получать объявления) |
| `broadcasts` | рассылки администратора: заголовок, текст, ссылка, аудитория (`all`/`clubs` + id кружков и занятий), автор, ключ идемпотентности, итоги доставки |
| `broadcast_schedules`, `broadcast_receipts` | запланированные рассылки и статусы/квитанции транспортов |
| `app_devices` | установки APK: случайный id установки (SHA-256), «мои кружки», переключатели объявлений и переносов, FCM-токен (если сборка с Firebase), платформа, версия, последний контакт (забываются через 60 дней) |
| `academic_periods`, `no_class_days` | учебные периоды и даты без занятий |
| `club_leaders`, `session_leaders`, `session_rooms` | дополнительные руководители кружков/занятий и аудитории занятий |
| `import_drafts`, `import_publications`, `schedule_row_revisions` | подготовка импорта, публикации и ревизии строк расписания |
| `notification_tasks` | отложенные задачи уведомлений |
| `usage_batches`, `usage_counters`, `client_error_counts` | добровольная ограниченная анонимная статистика и технические ошибки |

Ограничения: уникальность `(name, building)` у аудиторий; CHECK на день недели и порядок времени; каскадное удаление кружка → его занятия → исключения; удаление категории/руководителя/аудитории с зависимостями блокируется (409).

## Конкурентность
Запись защищена `asyncio.Lock` внутри процесса (проверка конфликта + commit — одна секция). Поэтому **ровно один воркер** (`--workers 1`). Масштабирование на несколько процессов требует PostgreSQL и блокировок/ограничений уровня БД.

## SQLite или PostgreSQL
SQLite остаётся штатным вариантом для одного экземпляра приложения. Ранее полученный замер (240 занятий, около 22 мс на `/api/schedule`) зависит от окружения и не является гарантией производительности; перед эксплуатацией измерьте реальную нагрузку. Переход на PostgreSQL нужен при нескольких экземплярах приложения; миграции Alembic упрощают смену СУБД, но сами по себе не обеспечивают межпроцессные блокировки.

## Бэкапы
`python server.py backup --dir /backups --keep 14` — консистентная копия через sqlite3 backup API, `integrity_check`, gzip, ротация. Проверка: `server.py verify-backup FILE`. Восстановление — `docs/runbook.md`.
