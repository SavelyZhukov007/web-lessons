# KipClub: что собирается и сколько хранится (с v1.9.024)

Своя обезличенная статистика без сторонних трекеров, cookie и рекламных идентификаторов. Включена по умолчанию,
выключатель «Анонимная статистика» в «Настройках → Конфиденциальность» работает одинаково на сайте, в iPhone PWA и в APK.

## Чего нет нигде

Имён, e-mail, телефонов, логинов, текста поиска, полного IP-адреса, полной строки User-Agent, точной геопозиции,
рекламных идентификаторов. Тексты отзывов в статистику не попадают.

## Уровень А: счётчики событий

- Клиент шлёт пачки `{metric, dim}` в `POST /api/app/usage` (до 50 событий, офлайн-очередь до 200 в `localStorage`).
- Метрики и значения `dim` только из закрытых списков (`backend/app/services/usage.py` → `METRICS`, `DIMS`):
  экраны, вид расписания, поиск и фильтры (без текста), календарь, 3D-тур, избранное, установка, пуши, обновления,
  ошибки API (раздел и класс ответа), скорость (LCP/INP/CLS/TTFB/FCP и время до расписания корзинами), JS-ошибки
  (тип, файл, строка, без текста и стека), падения APK (только подсистема), оценка 1..5 из карточки и формы.
- К каждой пачке: платформа (`web`, `pwa`, `ios`, `android`), канал сборки (`p`, `i`, `l`), версия `X.Y.ZZZ`.
- Сервер хранит только суммы по дням (`usage_daily`, `perf_daily`, `client_error_counts`); id пачки нужен для защиты
  от повторов и удаляется через 2 дня.
- Отдача APK сервером (`/android/download`) считается без выключателя и без каких-либо данных о человеке.

## Уровень Б: активность установки (для удержания)

- Раз в сутки (и при возврате в приложение не чаще раза в час) `POST /api/app/ping` со случайным id установки.
- Сервер хранит только `HMAC(секрет сервера, id)`: по нему нельзя восстановить id и связать с другими данными.
- На установку: платформа, канал, версия, первый и последний день, битовая маска активных дней за 120 дней.
- Из этого считаются DAU/WAU/MAU, когорты по неделям, D1/D7/D30 и доля версий.
- Установка без активности 120 дней удаляется.

## Сроки хранения

| Данные | Срок |
|---|---|
| Суммы по дням (события, скорость, ошибки, версии) | 90 дней, затем свёртка в `usage_monthly` |
| Итоги по месяцам и когорты | 2 года |
| Активность установки (HMAC) | 120 дней после последнего запуска |
| id пачек | 2 дня |
| Отзывы (`/data/feedback`) | последние 50 обращений |

Свёртку и чистку делает ежедневная задача (`usage.cleanup`: `rollup` + `compute_retention`).

## Выключатель

- Ключ `kc.anonymousUsage.v1` в `localStorage` (`0` = выключено). Старое значение `0` из версии с согласием
  сохраняется как «выключено».
- Выключено: не уходят ни события, ни ping, ни ошибки, ни скорость; очередь очищается.
- Service worker узнаёт о выключателе сообщением `kc:usage-switch` и перестаёт слать квитанции и счётчики пушей.
- APK получает его через `ItcNative.setUsage`, нативные квитанции пушей (`NotificationReceipts`) тоже перестают уходить.
- Админка (`/admin/*`) и демо-сборка не считаются никогда.

## Отзывы

- Форма: тип, текст, оценка 1..5 (необязательно), источник (настройки, «Что нового», карточка, экран ошибки, офлайн,
  встряхивание), скриншот, необязательный контакт для ответа.
- Технические данные прикладываются всегда: версия, платформа, ОС, браузер с главной версией, модель устройства,
  журнал ошибок. Полной строки User-Agent нет.
- Хранятся последние 50 обращений, выгрузка `tools/feedback_export.(py|ps1)` (SSH).

## Журналы сервера

- Журнал доступа приложения (`middleware.py`): IP маскируется до /24 (IPv4) и /48 (IPv6), User-Agent не пишется.
- Журнал Caddy и ротация журналов Docker не менялись (правка `deploy/Caddyfile` и compose только с отдельного OK).
- Журнал входов в админку хранит IP как журнал безопасности.
