# Бета v1.0.012

Android: versionName `v1.0.012`, versionCode `17`, внутренний build ID `v1.0.012pbA`, публичный канал без демо. GitHub-тег `v1.0.012` публикуется как prerelease, не как latest stable.

## Исправление скачивания

Основная кнопка /android/ использует /android/download и download_url из /api/app/android. Жёсткая зависимость от GitHub /releases/latest удалена: этот адрес не выбирает prerelease. Резервный адрес /download/kipclub.apk виден сразу и подписан явно.

Причина прежнего 404: в релизе v0.8.467pr был файл kipclub-v0.8.467prA.apk, но старые страницы запрашивали kipclub.apk. Для совместимости в тот же старый релиз добавлен точный исходный APK под именем kipclub.apk. Бета распространяется через серверный манифест и отдельный GitHub prerelease.

## Сборка и подпись

Команда: `node android/scripts/build.mjs --version v1.0.012pb --platform android --no-bump --no-demo --release`.

Release-вариант APK не имеет application-debuggable. Чтобы обновляться поверх прежней линии установок, сохранён прежний сертификат (Android Debug), SHA-256 сертификата: `9b3efa5f6d343cf7df7bcb8746d3b0dcd01ee240960b6306c7a6d0b80238363b`. Это совместимость существующей бета-линии, не новая ключевая инфраструктура для магазина приложений. Файлы ключей и пароли в репозиторий не добавляются.

## Выкат и откат

Перед пересборкой создаётся согласованная SQLite-копия через `server.py backup`, затем выполняется `verify-backup`. git pull --ff-only сохраняет локальные настройки сервера. Контейнер пересобирается через docker compose up -d --build. APK и latest.json обновляются только после проверки SHA-256 входящих файлов; предыдущие APK и манифест сохраняются для отката.

После выката проверить /readyz, главную, /android/, /api/app/android; скачать APK с основного и резервного адресов и сравнить SHA-256 с GitHub и локальной сборкой. Проверить, что метаданные содержат versionCode 17 и версию v1.0.012. При неудаче вернуть предыдущий образ/коммит и сохранённые APK + latest.json; восстановление БД требуется только при повреждении данных, а не автоматически при откате frontend.

Конфигурация домена, портов, HTTP/TLS и данные колледжа этим выпуском не заменяются. Проверка установки на физическом устройстве остаётся отдельной приёмкой.
