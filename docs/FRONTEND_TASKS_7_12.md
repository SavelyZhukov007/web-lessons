# Отчёт по задачам 7–12

Дата: 26 октября 2026 года. Изменения локальные, без коммита и push. Авторизационная часть frontend/js/api.js и серверная бизнес-логика не изменялись. Для тестов создавались отдельные временные БД.

## 7. Публичные страницы

- При переносе показаны новая аудитория и корпус, сейчас через соединение с /api/rooms. Ошибка справочника не блокирует карточку кружка, доступен повтор загрузки.
- В деталях расписания и подписях аудитория включает корпус. Длинные названия переносятся без раздвигания страницы.
- При более чем трёх параллельных полосах сетка переключается в читаемый список. Проверен сценарий с 40 одновременными занятиями.
- Компактнее отступы управления на телефоне. Кнопки дней/недель, поиск, совместные фильтры и сброс сохранены.
- Удалённый нижний блок не возвращён. Устаревшие ответы поиска не заменяют новые.

## 8. Административный интерфейс

- Формы блокируют повторное сохранение и закрытие во время запроса. Ошибка не очищает поля; причина показывается в форме.
- Непарольные черновики хранятся до суток в текущей вкладке. После перезагрузки нужно повторно открыть соответствующую форму. Пароли в хранилище не записываются.
- Исправлена отправка «Всем»: раньше обращение к отсутствующему session_ids могло ломать подтверждение.
- Исправлен журнал: API возвращает {items}, экрану нужен массив. Повтор загрузки журнала отделён от отправки.
- При сетевой ошибке сохраняются текст, аудитория и ключ идемпотентности, в том числе после перезагрузки вкладки. Повтор не превращается в новое объявление.
- Оценка охвата защищена от запоздавших ответов. Неудачная оценка не блокирует отправку; охват не обозначается как число прочитавших.
- Подписи нижней навигации сокращены для 320 px, полные названия доступны экранному диктору. Высота панели рассчитывается по фактической вёрстке.
- Выбор аудитории переноса и занятия включает корпус, чтобы одинаковые номера не путались.

## 9. PWA

- Проверка версии при открытии/возвращении, ручная проверка из настроек; метаданные версии обходят кеш.
- Обновлённый SW ожидает активации. Открытая форма откладывает перезагрузку; после сохранения/отмены можно применить новую версию.
- При обновлении запрашиваются свежие ресурсы. Проверка на временной сборке действительно меняет worker и CSS и подтверждает новую версию после перезагрузки.
- При смене push endpoint восстанавливаются выбранные кружки и настройка объявлений. При отсутствии достоверного согласия подписка на все не создаётся.
- PWA сверяет выбранные кружки с сервером, не доверяет только старому локальному списку. Проверены выключение и повторное включение уведомлений.
- Проверено повторное открытие без сети после загрузки данных, с явной отметкой резервной копии. Первый запуск до загрузки приложения требует сети.

## 10. Общие frontend-правила

- public-display.js: единые календарные даты и подписи аудитории/корпуса, используется публичными страницами и админкой.
- latest-request.js: отмена предыдущего запроса и защита от устаревшего результата в расписании и каталоге, включая задержку поиска.
- draft-state.js: единое хранение черновиков и сигнал о несохранённой форме для обновления PWA.
- Календарные ссылки сайта, PWA и нового APK используют серверный снимок текущей недели. Для старых ссылок оставлена совместимость; полное объединение всех Android-модулей не выполнялось.
- Стек остался HTML/CSS/JavaScript, авторизация api.js не менялась.

## 11. Старые настройки посещаемости

- Старые роли student/teacher переводятся в гостя без удаления избранного и предпочтений уведомлений. Действующая административная сессия не заменяется устаревшим значением роли.
- Ссылки QR/кабинета преподавателя направляются на расписание; удалена оставшаяся вкладка посещаемости в оболочке справочников.
- Проверены ярлыки manifest и отсутствие ссылок на удалённые экраны. Миграционные строки в исходниках оставлены намеренно.

## Проверки и ограничения

Проверяется готовая сборка приложения в Edge/Chromium через Playwright с реальным локальным FastAPI и временной БД. Основные размеры: 320, 360, 390 и 1366 px. Модульные тесты охватывают даты, цвета, фильтры, подписки, старые настройки, актуальность запросов и жизненный цикл SW. Для плотного расписания используются явно заданные тестовые события; CRUD/переносы/отправка/календарь проверяются настоящими запросами.

Итог: 87 модульных проверок (Node), 29 браузерных тестов (pytest e2e), 44 сценария PWA — успешно. git diff --check не обнаружил ошибок пробелов. Снимки сохранены вне репозитория в рабочем каталоге Codex: output/frontend-tasks-2026-10-26/screenshots и output/frontend-tasks-2026-10-26/pwa.

Команды: `node --test frontend/tests/*.test.mjs android/tests/*.test.mjs`, `python -m pytest e2e -q`, `python pwa/tests/run_pwa_tests.py`. Для этого запуска использовались локальный Python с зависимостями, Node из runtime Codex и Edge через E2E_CHROME/CHROME_PATH. Browser plugin недоступен, использован существующий Playwright-стенд. Проверки пустой страницы, ожидаемого содержимого, ошибок JS и взаимодействий включены в браузерные сценарии; снимки дополнительно просмотрены вручную.

Эмуляция iOS/Android в Chromium не заменяет физические устройства. Перед выпуском обязательны отдельные проверки Safari, установки/обновления APK и реальной push-доставки. Серверные задачи 13, 17 и 18 остаются у их исполнителей; новых полей backend, семестров и серверных тихих часов этот набор изменений не добавляет.
