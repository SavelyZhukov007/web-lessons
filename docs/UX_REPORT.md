> **Статус после доработок (`/workspace/itc/feature`, 23.10.2026).** Ниже — отчёт о ИСХОДНОМ `proj`. Что с найденными болями в `feature`:
> закрыто и проверено тестами/скриншотами — №1 (страница кружка), №2 (админка: CRUD, конфликты, отмены/переносы), №3 (логин в общем дизайне, выход, редирект с `?next`), №5 (кнопка .ics), №6 (каталог с карточками, поиском и фильтрами), №10 (favicon, HTML-404, robots); №7 частично (лимит дорожек + список, на 40 событиях не проверялось).
> **Не перепроверялось отдельно:** №4 (фильтр на телефоне показывает только день), №8 (тап-цели ≥ 44 px), №9 (запоминание фильтров/недели в URL). Новые скриншоты — `/workspace/itc/shots/key/` (светлая/тёмная тема, desktop/mobile, Material/iOS).


**Как тестировал:** копия проекта в `/workspace/itc/run`, venv `/workspace/itc/venv2`, `uvicorn` на `127.0.0.1:48987`, headless Google Chrome 156 + Playwright (python), вьюпорты **1366×768** и **390×844 (touch, DPR 2)**. Скрипты: `/workspace/itc/ux_walk.py`, `ux_states.py`, `ux_states2.py`; сырой лог: `/workspace/itc/ux_run.out`. Скриншоты — `/workspace/itc/shots/ux-d-*.png` (desktop) и `ux-m-*.png` (mobile); я их реально просмотрел, а не только считал DOM.

**Данные.** `backend.scripts.seed` — заглушка (`raise SystemExit("Заглушка…")`), поэтому я залил демо через админ‑API своим скриптом `/workspace/itc/seed_demo.py`: 5 направлений, 5 руководителей, 4 аудитории, 8 активных кружков + 1 скрытый, 14 занятий, 2 отмены (23.10 «Рисунок», 26.10 «Программирование») и 1 перенос (английский 23.10 → 24.10 11:00). Админ `admin` создан напрямую через `hash_password` (интерактивный `create_admin` через getpass в фоне не запустить). Сегодня в системе пятница 23.10.2026.

README **устарел** в нескольких местах (пишет «конфликты не проверяются», «админка — заглушки», «USE_MOCKS=true»): по факту моки выключены, а проверка пересечений работает — `POST /api/admin/sessions` на занятое время вернул 409 с описанием конфликта.

## Вердикт одной строкой
**Публичная часть (расписание) сделана хорошо и удобна, особенно на телефоне. Всё остальное — тонко: страница кружка пустая, админка — заглушка без выхода, нет .ics‑кнопки.** Для «студент посмотрел, когда занятие» — годится. Для «админ ведёт данные в браузере» — не годится вообще.

## Что работает хорошо (с доказательствами)
1. **Недельная сетка и мобильный «день за днём».** Desktop: сетка Пн–Сб с часовой шкалой, сегодняшний день подсвечен (`ux-d-01-home-full.png`). Mobile: переключатель дней Пн…Сб, стрелки «пред./след. день», переход Сб→Пн следующей недели работает (`ux-m-05-day-wrap-next-week.png`), открытый по умолчанию день — сегодня (`ux-m-01-home.png`). Горизонтального переполнения нет ни на одной странице (`docScrollW == clientW`: 1366/390).
2. **Отмены и переносы видны сразу.** Отменённое — зачёркнуто + красная подпись «Отменено», комментарий админа («Преподаватель на больничном») — в модалке (`ux-d-08-modal-cancelled.png`); перенос показан на новой дате с «Исходная дата: 23 октября» (`ux-d-08-modal-moved.png`). Счётчик «За выбранные дни: 13 · отменено: 1».
3. **Поиск/фильтры быстрые и осмысленные.** Поиск ищет и по названию, и по руководителю/аудитории (`ИВАНОВ` → 8 занятий, регистр не важен); фильтры направление/день/руководитель/аудитория; «Сбросить»; пустой результат — «Ничего не нашлось + Сбросить фильтры» (`ux-m-15-search-empty.png`). XSS‑строка `<script>…` в поиске безопасна, HTML в описании кружка выводится как текст (`ux-d-22-club-html-desc.png`).
4. **Состояния загрузки и ошибок продуманы.** Загрузка («Загружаем занятия…» при задержке 3 с, `ux-d-50-loading-state.png`), 500 → «Сервер временно недоступен», HTML вместо JSON → «неожиданном формате», остановленный backend → «Не удалось связаться с сервером» + «Повторить попытку» (`ux-m-53-backend-stopped.png`), после запуска сервера «Повторить» восстанавливает расписание. Падение справочников не ломает расписание («Не удалось загрузить список руководителей, аудиторий… Повторить загрузку фильтров», `ux-*-52-reference-error.png`). Быстрые 4 клика «вперёд» не ломают состояние (итог 16–21 ноября = ровно +4 недели).
5. **Клавиатура и доступность.** Есть skip‑link, видимый outline 2px на всём, Tab‑порядок логичен, Enter на карточке открывает `<dialog>` с фокусом внутри, Esc закрывает и возвращает фокус на карточку (desktop и mobile). Кнопки «неделя назад» работают по Enter и Space и не теряют фокус.

## Что неудобно или сломано (по убыванию боли)
1. **Страница кружка почти пустая** (`ux-d-21-club-page.png`, URL `/club.html?id=4`). Показывает только название и описание. README обещает: руководитель, контакты, аудитории, занятия, ближайшие изменения — `club.js` берёт из ответа API только `name` и `description`. Чтобы узнать, когда занятия, надо вернуться на главную и искать в сетке. Критерий ТЗ «найти кружок и расписание за 3 клика» формально выполним только через главную.
2. **Админка — заглушка** (`ux-d-44-admin-after-login.png`): после успешного входа — «Заготовка админки… Здесь будут списки и формы», ни одной кнопки (`buttons: 0`). **Кнопки «Выйти» нет** (только API `POST /api/admin/logout` → 204 работает). `/admin/` без входа отдаёт ту же заглушку без редиректа на логин (`ux-d-40-admin-unauth-direct.png`) — данных там нет, но защиты страницы тоже нет (API при этом честно даёт 401: `/api/admin/status|clubs|exceptions`). Страница логина, будучи уже залогиненным, снова показывает форму (`ux-d-45-login-when-authed.png`). Поэтому весь «вход/выход/админ» сегодня проверяется только через /docs.
3. **Экран логина выглядит как другой сайт** (`ux-m-43-login-wrong.png`): дефолтный стиль (`common.css`) вместо дизайна кружков, шапка «Расписание · Кружки · Админка» вместо брендовой, плашка «Шаблон: вымышленные данные, функции ещё не реализованы» видна пользователю. Ошибки: пустое поле — нативное **английское** «Please fill out this field.»; короткий логин/пароль — сырой pydantic «String should have at least 3 characters». Поля 32 px высотой (< 44 px). Неверный пароль — понятно: «Неверный логин или пароль». Блокировка после 5 попыток работает: «Слишком много неудачных попыток… через 299 секунд» (`ux-m-54-login-lockout.png`), и верный пароль во время блокировки тоже отклоняется (ожидаемо, но пользователю не объясняется, что ждать надо и с верным паролем).
4. **На телефоне фильтр показывает только выбранный день.** Включил «Спорт» в пятницу → «За день: 0 · фильтры включены» (`ux-m-11-filter-category.png`), хотя на неделе 2 занятия волейбола. Нет подсказки «есть в другие дни»; в переключателе дней нет индикаторов, где есть занятия. Плюс при открытых фильтрах расписание уезжает ниже экрана (`ux-m-10-filters-open.png`), результат пустого поиска виден только после скролла (`ux-m-15-search-empty.png`). Плейсхолдер поиска обрезается («…аудитор»).
5. **Нет кнопки .ics.** Эндпоинт есть и рабочий (`GET /api/clubs/1/calendar.ics?week=2026-10-19` → 200, `text/calendar`, `Content-Disposition: attachment; filename="club-1-2026-10-19.ics"`, 52 строки), но ни на странице кружка, ни в модалке ссылки нет. Без ссылки функция для пользователя не существует.
6. **Список кружков — просто 8 ссылок** (`ux-d-20-clubs.png`): нет направления, руководителя, фильтра, поиска, количества занятий. Работает, но «каталогом» не является.
7. **Мелкие карточки в сетке.** При пересечении по времени карточки сужаются до 1/3 колонки: «Программир|ование дл…» (`ux-d-01-home-full.png`, вторник/среда); у 2 карточек контент обрезан (бейдж «Перенос» у английского 11:00–12:30 виден наполовину). Подсказка на странице сама признаёт: «Короткие занятия удобнее смотреть списком». Режим «Список» (`ux-d-16-list-view.png`) читается лучше, но по умолчанию включена сетка. На 1366×768 первый экран показывает только ~09:00–13:00 (80 px на час), остальное — скролл.
8. **Тап‑цели < 44 px** (измерил автоматически): шапка/ссылки навигации 26–30 px по высоте; «Вход для сотрудников» 15 px на mobile; стрелки недели 40×44, стрелки дня 30×44; футерная ссылка 18 px; «О кружке» 20 px; «К списку кружков» 20 px. Основные карточки и кнопки дней — нормальные.
9. **Состояние не запоминается.** Фильтры, выбранная неделя и день теряются при перезагрузке; в URL ничего нет, поделиться ссылкой «неделя + фильтр» нельзя.
10. **Мелочи.** Нет favicon (404 в консоли на каждой странице: `Failed to load resource … 404`). Несуществующий URL (`/nonexistent-page.html`) → голый JSON `{"detail":"Not Found"}` (`ux-d-24-404-page.png`). Модалка не закрывается кликом по фону (только «Закрыть»/Esc). Выбор даты `9998-12-24` молча игнорируется (метка остаётся «1900»). `/club.html?id=999` → «Кружок не найден» (ок), но `<title>` остаётся «Кружок — КИПФИН». Date‑picker показывает формат `мм/дд/гггг` — это локаль headless‑Chrome, на русской системе будет иначе (не баг сайта). Нативный date‑input занимает 4 Tab‑остановки (так у всех браузеров).

## Что проверено и ОК (без замечаний)
Консольных JS‑ошибок нет (все «errors» в логе — мои намеренные запросы на 404/401/422 + favicon). Падений сети: только `ERR_ABORTED` у отменённых прежних запросов при быстрых кликах (штатная отмена `AbortController`). Битых внутренних ссылок нет. Неверные недели в API: `week=garbage` → 422 с русским текстом, `week=2026-10-21` (не понедельник) → 422 «должен указывать на понедельник», `week=0001-01-01` → 200 (ок). Скрытый кружок не попадает в публичный список. Гонка запросов при быстрых кликах обрабатывается корректно.
