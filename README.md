# Расписание кружков колледжа

Веб-приложение, в котором студенты и преподаватели находят актуальное расписание кружков, а администраторы ведут данные и публикуют отмены и переносы.

Ниже описан **целевой функционал по исходному ТЗ**, а не заявление о готовности всех возможностей. Фактический статус указан отдельно. Исходник требований: «ТЗ_расписание_кружков.docx». Frontend по решению команды реализуется на чистом HTML/CSS/JavaScript, backend — Python/FastAPI.

## Для кого

- Посетитель без входа: расписание, кружки и справочная информация.
- Администратор: управление данными через защищённый интерфейс.

Публичной регистрации нет. Администраторы создаются вручную командой. Руководители кружков хранятся как справочник и не имеют аккаунтов.

## Обязательный функционал конечной версии

### Публичная часть

- Главная с недельным расписанием, понедельник–суббота, занятия расположены по времени.
- Переключение выбранной недели.
- Фильтры по направлению, дню недели, руководителю и аудитории.
- Поиск по названию кружка.
- Список активных кружков карточками с фильтром по направлению.
- Страница кружка: описание, направление, руководитель, контакты, аудитории, занятия и ближайшие изменения.
- Отменённые занятия видны с подписью «отменено»; перенесённые показаны на новом времени с соответствующей подписью.
- Удобный интерфейс на телефоне — основной сценарий использования; полноценный вид на компьютере.

### Административная часть

- Вход и выход; защита всех административных API-маршрутов.
- Просмотр, создание, изменение и удаление кружков, направлений, руководителей и аудиторий.
- Управление регулярными занятиями: кружок, день недели, время и аудитория.
- Скрытие кружка через признак неактивности без удаления данных.
- Отмена конкретного занятия на дату без изменения регулярного расписания.
- Перенос конкретного занятия на новую дату, время и аудиторию без изменения регулярного расписания.
- Отказ в сохранении при пересечении занятости одной аудитории или одного руководителя; понятное объяснение конфликта.

### Общие требования

- Пароли только в виде стойкого хеша; текущая реализация использует scrypt.
- Параметризованные запросы к БД и безопасный вывод пользовательского содержимого.
- Время в 24-часовом формате, занятия в пределах 08:00–21:00, начало раньше конца.
- Тестовые данные и инструкция запуска на чистой машине.
- Целевое время открытия страницы — менее двух секунд при обычном интернете; подлежит измерению на согласованном окружении.
- Git/GitHub, задачи и изменения через Pull Request с ревью.

### Дополнительные возможности — после обязательной части

Эти пункты исходного ТЗ относятся к разделу «Если успеем»:

- Экспорт расписания кружка в календарь (.ics).
- Тёмная тема.
- Журнал действий администраторов.
- Страница «Что изменилось на этой неделе».

## Критерии приёмки из ТЗ

1. Посетитель без входа находит кружок и его расписание за три клика.
2. Администратор создаёт кружок с двумя занятиями в неделю; кружок появляется в общей сетке.
3. Два занятия в одной аудитории в одно время не сохраняются; пользователь получает понятное сообщение.
4. Отмена занятия на конкретную дату видна публично и не меняет регулярное расписание.
5. Неавторизованный запрос к административному API получает 401.
6. Приложение запускается по инструкции на чистой машине.

Отдельно проверяется запрет одновременных занятий одного руководителя, переносы между неделями и мобильный интерфейс.

## Быстрый запуск

Все команды выполнять из корня репозитория. Нужны Python 3.10+ с pip и модулем venv. Репозиторий перед этим клонировать через Git или скачать архивом.

### Windows / PowerShell

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock.txt
.\.venv\Scripts\python.exe server.py
```

### macOS / Linux

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install -r backend/requirements.lock.txt
./.venv/bin/python server.py
```

Открыть http://127.0.0.1:8000/ . Документация API: http://127.0.0.1:8000/docs . Проверка сервера: http://127.0.0.1:8000/api/health . Остановка — Ctrl+C.

HTML нужно открывать через сервер, а не двойным кликом. server.py запускает локальный сервер с автоматической перезагрузкой; это не конфигурация production.

### Создание администратора

В другом терминале из корня проекта:

```powershell
# Windows
.\.venv\Scripts\python.exe -m backend.scripts.create_admin --login admin
```

```bash
# macOS / Linux
./.venv/bin/python -m backend.scripts.create_admin --login admin
```

Пароль и подтверждение запрашиваются интерактивно. Пароль не передавать в аргументах и не коммитить. Эта команда создаёт аккаунт backend; вход в браузере пока требует доработки интерфейса.

### Тестовые данные

Источник вымышленных примеров: data/sample-data.json. Браузерный мок: frontend/mock-data.json. Загрузчик `python -m backend.scripts.seed` пока не реализован и не заполняет БД. Сейчас backend можно наполнить через /docs после авторизации в POST /api/admin/login. Не включать реальные пароли и персональные данные в публичные примеры.

Frontend пока работает с USE_MOCKS=true в frontend/js/api.js. Не переключать на false до подключения нужных методов и обработки ошибок. Переключение API не должно незаметно возвращать моки при ошибке сервера.

Базы, .venv и секреты в Git не добавлять.

## API

Публичные маршруты: GET /api/clubs, /api/clubs/{id}, /api/schedule?week=YYYY-MM-DD, /api/categories, /api/leaders, /api/rooms.

Административные: POST /api/admin/login и /logout; GET /api/admin/status; GET/POST коллекций и PATCH/DELETE объектов /api/admin/categories, /leaders, /rooms, /clubs, /sessions. Исключения: GET /api/admin/exceptions, POST /api/admin/exceptions/cancellations, POST /api/admin/exceptions/moves, PATCH/DELETE /api/admin/exceptions/{id}.

Актуальные тела запросов — в /docs, дополнительные договорённости — docs/api-contract.md. В исходном ТЗ редактирование обозначено PUT, текущая реализация использует PATCH: перед сдачей согласовать это различие и обновить контракт либо добавить PUT.

ID — integer; дата YYYY-MM-DD; время HH:MM; weekday 1–6. Отмена cancelled, перенос moved. event_id обозначает конкретное занятие, session_id — регулярную серию. Ошибки: 401, 404, 409, 422. Сейчас 409 не означает, что все пересечения времени уже проверяются.

## Тестирование

```powershell

```

```bash
./.venv/bin/python -m pytest backend/tests -q
```

Незавершённые и пропущенные проверки описывать явно. Перед сдачей нужен сквозной сценарий: создать кружок и два занятия → увидеть публично → отклонить конфликт → отменить и перенести → проверить телефон и доступ без входа.

## Публикация и сопровождение

Перед публикацией завершить проверку конфликтов, подключение интерфейсов и тестовые данные. Настроить HTTPS, Secure-cookie для production, защиту изменяющих запросов и ограничение попыток входа. Сейчас cookie имеет Secure=false для локальной разработки. Проверить доступ и безопасный вывод; подготовить резервное копирование SQLite и восстановление.

Назначить человека, обновляющего данные, и ответственного за техническое сопровождение. Деплой и работа на хостинге ещё не подтверждены.
