# Расписание кружков колледжа

Правила текущего выпуска, совместимость старых клиентов, смысл экспорта, уведомления и сценарий демонстрации: [docs/PRODUCT_RULES.md](docs/PRODUCT_RULES.md). Учебные периоды пока требуют серверной реализации.

Веб-приложение, в котором студенты находят актуальное расписание кружков, а администраторы ведут данные, публикуют отмены и переносы и рассылают объявления.

Ниже описан **целевой функционал по исходному ТЗ**, а не заявление о готовности всех возможностей. Фактический статус указан отдельно. Исходник требований: «ТЗ_расписание_кружков.docx». Frontend по решению команды реализуется на чистом HTML/CSS/JavaScript, backend — Python/FastAPI.

## Для кого

- Посетитель без входа: расписание, кружки и справочная информация.
- Администратор: управление данными через защищённый интерфейс.

Публичной регистрации нет. Администраторы создаются вручную командой. Руководители кружков хранятся как справочник и не имеют аккаунтов.

## Обязательный функционал конечной версии

### Публичная часть

- Главная с недельным расписанием, понедельник–суббота, занятия расположены по времени.
- Переключение выбранной недели.
- Фильтры по направлению, дню недели, руководителю и аудитории.
- Поиск по названию кружка.
- Список активных кружков карточками с фильтром по направлению.
- Страница кружка: описание, направление, руководитель, контакты, аудитории, занятия и ближайшие изменения.
- Отменённые занятия видны с подписью «отменено»; перенесённые показаны на новом времени с соответствующей подписью.
- Удобный интерфейс на телефоне — основной сценарий использования; полноценный вид на компьютере.

### Административная часть

- Вход и выход; защита всех административных API-маршрутов.
- Просмотр, создание, изменение и удаление кружков, направлений, руководителей и аудиторий.
- Управление регулярными занятиями: кружок, день недели, время и аудитория.
- Скрытие кружка через признак неактивности без удаления данных.
- Отмена конкретного занятия на дату без изменения регулярного расписания.
- Перенос конкретного занятия на новую дату, время и аудиторию без изменения регулярного расписания.
- Отказ в сохранении при пересечении занятости одной аудитории или одного руководителя; понятное объяснение конфликта.

### Общие требования

- Пароли только в виде стойкого хеша; текущая реализация использует scrypt.
- Параметризованные запросы к БД и безопасный вывод пользовательского содержимого.
- Время в 24-часовом формате, занятия в пределах 08:00–21:00, начало раньше конца.
- Тестовые данные и инструкция запуска на чистой машине.
- Целевое время открытия страницы — менее двух секунд при обычном интернете; подлежит измерению на согласованном окружении.
- Git/GitHub, задачи и изменения через Pull Request с ревью.

### Дополнительные возможности — после обязательной части

Эти пункты исходного ТЗ относятся к разделу «Если успеем»:

- Экспорт расписания кружка в календарь (.ics).
- Тёмная тема.
- Журнал действий администраторов.
- Страница «Что изменилось на этой неделе».

## Критерии приёмки из ТЗ

1. Посетитель без входа находит кружок и его расписание за три клика.
2. Администратор создаёт кружок с двумя занятиями в неделю; кружок появляется в общей сетке.
3. Два занятия в одной аудитории в одно время не сохраняются; пользователь получает понятное сообщение.
4. Отмена занятия на конкретную дату видна публично и не меняет регулярное расписание.
5. Неавторизованный запрос к административному API получает 401.
6. Приложение запускается по инструкции на чистой машине.

Отдельно проверяется запрет одновременных занятий одного руководителя, переносы между неделями и мобильный интерфейс.

## Быстрый запуск

Python 3.10+ с pip и venv. Все команды — из корня репозитория.

```powershell
# Windows / PowerShell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock.txt
.\.venv\Scripts\python.exe server.py admin create admin      # пароль ≥ 10 символов
.\.venv\Scripts\python.exe server.py seed                    # (необязательно) демо-данные
.\.venv\Scripts\python.exe server.py                         # http://127.0.0.1:8000, авто-перезагрузка
```

```bash
# macOS / Linux
python3 -m venv .venv
./.venv/bin/python -m pip install -r backend/requirements.lock.txt
./.venv/bin/python server.py admin create admin
./.venv/bin/python server.py seed
./.venv/bin/python server.py
```

Админка: http://127.0.0.1:8000/admin/login.html. HTML открывать только через сервер. Пароль админа передаётся запросом, `--password-stdin` или переменной `ADMIN_PASSWORD` — не аргументом командной строки.

### Команды `server.py`

| Команда | Что делает |
|---|---|
| `server.py` | как раньше: dev-сервер 127.0.0.1:8000 с авто-перезагрузкой |
| `server.py serve --host H --port P [--frontend DIR] [--no-reload]` | запуск сервера (в `ENV=production` перезагрузка отключена принудительно) |
| `server.py build web\|pwa\|android\|back\|all` | сборки в `builds/`: сайт, PWA, APK, релиз бэкенда; см. `FEATURE_README.md` |
| `server.py admin create\|reset-password\|list` | управление администраторами (сброс пароля завершает все сессии) |
| `server.py seed [--dry-run]` | идемпотентная загрузка `data/sample-data.json` |
| `server.py backup` / `verify-backup FILE` | консистентный бэкап SQLite (sqlite3 backup API, gzip, ротация) и проверка |
| `server.py check-config` | проверка прод-конфигурации (то же, что делает приложение при старте) |

### Сборки под платформы и раздача приложения

**Android** — `python server.py build android`

* Поднимает версию в `android/version.json` (versionCode +1, versionName 1.0 → 1.1 → 1.2 …) — каждый APK ставится поверх предыдущего; пакет `ru.kipfin.clubs` (демо — `ru.kipfin.clubs.demo`).
* Основной APK: **release**, если заданы `ANDROID_KEYSTORE` (путь к `.jks`), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` [, `ANDROID_KEY_PASSWORD`]; без ключа — debug-подпись (для тестов). Ключ и пароли — только вне репозитория: обновления (и в RuStore) принимаются лишь с той же подписью.
  Создать ключ: `keytool -genkeypair -v -keystore kruzhki-release.jks -alias kruzhki -keyalg RSA -keysize 4096 -validity 10000`.
* Затем собирается демо-вариант (`kipclub-demo-debug-<версия>.apk`, офлайн, без сервера) с той же версией.
* Результат: `builds/android/*.apk` + `.sha256`; основной APK публикуется в `releases/android/` (`APP_RELEASES_DIR`) вместе с `latest.json` — его сразу отдаёт сайт.
* Флаги: `--demo` (только демо), `--no-demo`, `--no-publish`, `--server-url URL`, `--check-only`, `--install`.

**iPhone (PWA)** — `python server.py build pwa` (псевдоним `build ios`)

* Сайт + service worker + `manifest.webmanifest`; apple-touch-icon 120/152/167/180, `apple-mobile-web-app-*`, экраны запуска для 12 размеров iPhone (SE … 16 Pro Max) в светлой и тёмной теме, `theme-color` для светлой и тёмной схем.
* Результат: `builds/pwa/` — раздавать по HTTPS: `python server.py serve --frontend builds/pwa`.

**Страницы установки на сайте**

| Адрес | Что там |
|---|---|
| `/ios` | пошаговая установка на iPhone (Safari → «Поделиться» → «На экран “Домой”»); если открыто не в Safari — подсказка и кнопка «Скопировать ссылку» |
| `/ios/pwa` | ссылка для рассылки: в установленном приложении сразу открывает расписание, в браузере — окно с инструкцией |
| `/android/` | кнопка «Скачать APK» (версия, размер, SHA-256), инструкция по «неизвестным источникам», блок RuStore |
| `/android/download` | последний APK из `APP_RELEASES_DIR` (`latest.json` или самый свежий `*.apk`), `application/vnd.android.package-archive`; нет локального релиза — 307 на GitHub Releases: ${G} |
| `/api/app/android` | метаданные релиза для страницы (JSON) |

На главной, «Все кружки» и странице кружка телефон видит небольшую плашку «Установить приложение» (iPhone → `/ios`, Android → `/android/`); её нет на компьютере, в установленном PWA и в APK, закрытие скрывает её на 30 дней.
Блок RuStore появится на `/android/`, когда задать `RUSTORE_URL=https://www.rustore.ru/catalog/app/…`.

## Роли и объявления

**Роли только две.** Гость смотрит расписание, отмечает «мои кружки» и получает уведомления; администратор ведёт данные в админке.
На первом запуске приложения: «Смотреть расписание» или «Я сотрудник — войти в админку» (логин/пароль, как на сайте).
Посещаемость по QR удалена целиком (сканер, камера, `qr.html`, офлайн-очередь отметок, ID студента, привязка устройства, статистика и Excel):
миграция Alembic `0007` удаляет таблицы `attendance`, `qr_nonces`, `student_devices`. Старые роли «студент»/«преподаватель» на телефоне
при обновлении превращаются в гостя, а локальные данные профиля студента стираются. Роль преподавателя удалена ещё раньше (миграция `0006`).

**Рассылки (админка → «Рассылки»).** Заголовок (до 80 символов), текст (до 500), что открыть по нажатию (расписание, каталог или страница кружка),
кому: «Всем» или «Кружкам» (поиск, выбор кружков и при желании отдельных занятий). Экран показывает предпросмотр уведомления и оценку охвата,
перед отправкой спрашивает подтверждение; повторное нажатие не создаёт дубль (ключ идемпотентности, плюс защита от одинакового текста в течение 2 минут).
Ниже — журнал: когда, кто, кому, текст, сколько доставлено.

API: `GET /api/admin/broadcasts`, `POST /api/admin/broadcasts/estimate`, `POST /api/admin/broadcasts` (только администратор),
публичный `GET /api/announcements?since=&clubs=&device=&off=` для приложения, `POST /api/push/preferences` — переключатель «Объявления» для браузера.

**Доставка.**
* Сайт и PWA — Web Push сразу при отправке: всем подпискам браузера с включёнными «Объявлениями»; адресное объявление получают подписчики выбранных кружков
  и подписчики «всех изменений». Одно устройство — одно уведомление.
* APK (без Google Play Services) — приложение само забирает новые объявления при открытии и в фоне примерно раз в 30 минут (WorkManager),
  канал уведомлений «Объявления». Показанный id запоминается — повторов нет; на первом запуске старые объявления не показываются.
  Адресные объявления приходят, если кружок отмечен в «Моих кружках». В журнале для APK показывается число активных установок (опрашивали сервер за 30 дней).

Отключить объявления: в приложении — «Напоминания и виджеты» → «Объявления от администрации», на сайте — «Настройки» → «Объявления».
Переносы и отмены приходят независимо от этого переключателя.

## Версии (общие для всех платформ)

Полный идентификатор: `v<X.Y.Z><канал><стадия><платформа>`, например `v0.4.312pdA`.

- `X.Y.Z` — общий номер для APK, веба и iPhone PWA, лежит в `version.json` в корне. Повышается по смыслу изменений: Z — исправления, Y — новые возможности, X — несовместимые изменения.
- Канал (задаёте вы): `l` — local, личная проверочная сборка (демо-данные, подключение к тестовому серверу, логи, вход в демо одной кнопкой); `i` — internal, для команды ИТС (пока как `l`, но со своим конфигом); `p` — public, пользовательская сборка без тестового сервера, логов, демо-входа и прочих отладочных опций. Посещаемости и QR-отметок нет ни в одном канале.
- Стадия (задаёте вы): `a` — alpha, `b` — beta (бета-тестирование), `d` — исправления после alpha, `r` — release. Пользовательское название текущей беты — `v1.0.012`, внутренний идентификатор сборки — `v1.0.012pbA`. versionCode — 17.
- Платформа (её дописывает скрипт, вручную не вводится): `A` — Android APK, `W` — веб в браузере, `M` — iPhone PWA.

Сборка:

```
cd android
node scripts/build.mjs --version v0.4.312pd --platform android   # → builds/android/v0.4.312pdA/kipclub-v0.4.312pdA.apk
node scripts/build.mjs --version v0.4.312la --platform all       # android + web + pwa
```

Формат проверяется регулярным выражением `^v\d+\.\d+\.\d+[lip][adr]$`. Номер из `--version` записывается в общий `version.json`. `versionCode` Android растёт на 1 при каждой сборке (`--no-bump` — не поднимать); он хранится в `android/version.json`. Результат кладётся в `builds/<платформа>/<полный id>/`: сборки с разными id лежат рядом, а пересборка того же id заменяет только свою папку. В PWA номер доступен как `/version.json` и `window.ITC_VERSION`.
