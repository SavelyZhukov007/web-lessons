# Безопасность

## Авторизация администратора

- регистрация через браузер отсутствует;
- учётные записи создаются только вручную через `python -m backend.scripts.create_admin`;
- все маршруты `/api/admin/*`, кроме `POST /api/admin/login`, требуют действующую cookie-сессию и возвращают `401`, если пользователь не вошёл.

## Хранение паролей

- пароли не передаются в аргументах CLI и не логируются;
- в таблице `admins` хранится только `password_hash`;
- для хеширования используется `scrypt` со случайной солью — это надёжный KDF, допустимый как аналог bcrypt.

## Серверные сессии

- после успешного входа сервер создаёт случайный токен сессии;
- в cookie хранится только сам токен, а в БД — его `SHA-256`-хеш;
- cookie `HttpOnly`, `SameSite=Lax`, срок жизни — 7 дней;
- при выходе сессия удаляется из базы и cookie очищается.

## Что ещё важно

- авторизация не хранится в `localStorage`;
- публичные маршруты не открывают `password_hash` и данные сессий;
- в текущей версии отсутствует автоматическая доменная проверка конфликтов расписания при сохранении административных изменений — это остаётся отдельной задачей.
